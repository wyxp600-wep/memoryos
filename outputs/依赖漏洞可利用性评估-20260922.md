**6 项依赖漏洞在当前部署形态下全部不可利用**——但**其中 3 项的「不可利用」依赖代码现状**，

## 三、逐项证据

### 3.1 protobufjs / onnxruntime-web / onnx-proto（含 critical）

**依赖链**：`@xenova/transformers@2.17.2` → `onnxruntime-web@1.14.0` → `onnx-proto` → `protobufjs@6.11.6`（受影响范围 `<=7.6.2`）

**第一层事实**：`node_modules/@xenova/transformers/src/backends/onnx.js:19-22` 是**静态导入两条运行时**——
注释自称「理想情况下按需导入」，实际代码并非如此：

```js
import * as ONNX_NODE from 'onnxruntime-node';
import * as ONNX_WEB from 'onnxruntime-web';
```

**关键分支**（同文件 `:32-37`）：

```js
if (typeof process !== 'undefined' && process?.release?.name === 'node') {
    ONNX = ONNX_NODE.default ?? ONNX_NODE;   // ← Node 下只用 onnxruntime-node
    executionProviders.unshift('cpu');
} else { /* 浏览器才用 ONNX_WEB → onnx-proto → protobufjs */ }
```

**实证**（Node loader 钩子 + 真实生产路径 `getEmbedder()` → `embedTexts()`，加载 543MB BGE-M3 并成功产出 1024 维向量）：

```
被加载：  onnxruntime-node/dist/index.js
          onnxruntime-web/dist/ort-web.node.js   ← 仅副作用
          sharp/lib/index.js
未加载：  protobufjs        ← 零命中
          onnx-proto        ← 零命中
```

**旁证**：全仓 `dist/*.js` 对 `protobufjs|onnx-proto|onnxruntime-web` **零引用**。

**结论**：这 6 条 advisory（任意代码执行 / 代码注入 / 原型注入 / DoS）全部依赖 protobufjs 的
**代码生成或解析**路径——本项目根本不进入该路径。

### 3.2 sharp（含 libvips / libheif CVE）

**通告原文**：*"Those processing **untrusted input** with versions of sharp prior to 0.35.0 are affected"*
**CVSS v4**：`AV:L`（本地攻击向量）

**项目侧事实**：`dist/*.js` 中检索 `sharp|RawImage|ImageFeatureExtractor|jpeg|png|libvips` → **零命中**。
sharp 在 transformers 内仅由 `src/utils/image.js` 的图片预处理调用，而本项目只跑
`feature-extraction` 的**文本**模型（BGE-M3），图片解码函数从不被喂入数据。

### 3.3 echarts（CVE-2026-45249）

**通告触发条件**（需**同时**满足 4 条）：
1. 使用 **Lines series**（`series-lines`）
2. 使用 tooltip
3. **未**自定义 `tooltip.formatter`
4. 指定 `series.data[i].name`

此时 `name` 中的原始 HTML 会经 innerHTML 注入 tooltip 内容。

**项目侧事实**：

| 检查 | 结果 |
|---|---|
| 前端 `app.js` 中 `'lines'` 出现次数 | **0** |
| 实际使用的 series 类型 | `pie`×6、`line`×6、`bar`×2、`graph`×2、`scatter`×1 |
| tooltip 配置点 | 9 处，其中 3 处已自定义 formatter，图谱那处用 `esc()` 转义 |

第 1 条即不满足 → 不可利用。

## 六、验证方法（可复现）

### 6.1 「某模块是否真的被加载」——Node loader 钩子

```js
// hook.mjs
import fs from "node:fs";
export async function load(url, ctx, next) {
  if (/protobufjs|onnx-proto|onnxruntime|sharp/.test(url)) fs.appendFileSync(process.env.PROBE_LOG, url + "\n");
  return next(url, ctx);
}
// register.mjs
import { register } from "node:module";
register("./hook.mjs", import.meta.url);
```

运行：`node --import file:///.../register.mjs <探针脚本>`

**三个坑**：
1. `--import` **必须用 `file://` URL**，传 `C:/...` 会报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`
2. 探针脚本必须放在**目标包所在目录内**（放 TEMP 会解析不到 `node_modules`）
3. **静态「导入了」≠「加载了」**——`import * as X from 'y'` 只保证 y 被加载，y 内部对 z 的引用可能是惰性的；
   必须跑**真实调用路径**才能定论

### 6.2 依赖审计

```powershell
npm audit --registry=https://registry.npmjs.org
```

**必须显式指定官方 registry**——npmmirror 未实现安全公告端点，直接跑会报
`NOT_IMPLEMENTED /-/npm/v1/security/*`。
