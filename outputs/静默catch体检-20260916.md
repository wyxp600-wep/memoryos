# 静默 catch 体检报告（2026-09-16 · A 分区验收）

> 工具：`resources/memoryos/dist/lint-silent-catch.js`（内建 `--self-test` 自证"对坏样本报警、对好样本不误报"）
> 触发原因：本轮 `task_release` 的卡片侧 UPDATE 因「实参多于占位符」抛 `column index out of range`，
> 被 `catch {}` **静默吞掉** ⇒ 语句未执行、外观与成功无异。故全仓体检同一缺陷类。
> 口径：默认只扫**生产文件**（44 个）；测试脚本与开发工具（smoke 系列 / lint 系列 / snapshot-routes / audit-probe）不纳入。

## 二、真风险（已修）

| 位置 | 场景 | 静默的后果 | 处理 |
|---|---|---|---|
| `server.js` `syncTaskToCard()` | MCP 改任务头 → 卡片状态同步 | 「MCP 已领取/已完成，看板卡仍 ready」——两侧不一致且无迹可循（只能等 C-5 对账 5 分钟兜底） | ✅ 加 `console.error` |
| `dashboard-reg-cards.js` `syncCardToTask()` | 看板卡流转 → 任务状态头回写 | 「卡已流转、任务头未跟」同上 | ✅ 加 `console.error` |

> 这两处是**双向状态同步**的两个方向，也是本轮两次真实缺陷的同一类：状态同步失败被静默 = 三方漂移 +
> 排障无线索。加日志成本 1 行、语义不变。

## 六、工具本身的两次自纠（记录，避免复用踩坑）

1. **反查 try 会误报**：初版从 `catch` 往回 2000 字找 `try`，可能匹配到另一个 try 块；改为**正向遍历 `try`**，
   判定逻辑与 `--self-test` 完全同一套（"自测过的规则 = 实际用的规则"）。
2. **漏认项目自带日志封装**：`logDaemon(` / `logAudit(` 未计入"有日志" ⇒ 误报；已补。
   另：`JSON.parse` 兜底应从 MED 降为 LOW（非 IO）。
3. **块注释里写 `*/` 会截断注释**（写 `smoke-*/lint-*` 触发语法错误）——注释里避免出现 `*/` 组合。

**复现**：`npm run lint:silent`（默认生产范围）｜`npm run lint:silent -- --all-files`（含测试脚本，噪声大，仅排查用）｜`--self-test`（校验器自证）
