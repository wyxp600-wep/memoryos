## 一句话结论

Orca 能把任务「拍给 agent」的本质是：**每个任务在执行时有且只有一个权威尝试（work 证）+ 干完必须由
agent 自己交回（worker_done）**；MemoryOS 不需要照抄它的四分离架构，用现成的
「卡片 CAS 认领 + `dispatches` 表 + 网页 run」三件套接线即可复刻同一保证——A1 批已打通（提交 `60bc476`）。

## 关键实现事实（回查用）

1. **起 run 单一路径**：`ctx.startAgentRun`（knowledge 域注入），`POST /api/agent/runs` 也改走它——
   排队（cap=maxConcurrent）/直接开跑只有一份逻辑，派发端点与聊天端点不会漂移。
2. **工作证投影**：`claim_lock = dispatch_key`（同一次 randomBytes(12)），卡片侧零权威字段，
   核对身份只比对这一个值。
3. **收口三层幂等**：`finalizeCardDispatch` ①卡已不在 running 只补结算 ②`settleDispatch` 自带
   `WHERE state='active'` 守卫 ③全程 try 包裹不反噬 run 终态。MCP `task_done` 先收口也无冲突。
4. **强制收尾轮**：绑定任务的派发 run 若跑完没调 task_done → 补一枪
   `runAgent({ maxSteps:2, toolsFilter:["task_done"] })`（对标 `dist/agent.js:216` CLI 版）。
5. **abort 排队 run 也收口**：`dispatchRuns` 反查表（runId→cardDispatch，上限 200），
   否则排队中被中止的 run 永远不进 startRun，卡片永远 running。
6. **不留半开状态**：起 run 失败 → 事务回滚（卡回 ready + `releaseDispatch` + `dispatch_failed` 事件）。

## 踩坑（下次直接绕开）

- **走查断言禁取中间态**：LLM 不可用时 run 约 1-4 秒即 failed 收口，断言「派发后=running」会随机红。
  正确姿势是断**不变量**（key=回执 key、锁已清）和**终态**（card∈{review,failed}、dispatch=settled）。
- **a11y 走查硬编码旧路由会碎**：`a11y-ui-walk.mjs:243` 原点 `.nav-item[data-route="all"]`，
  Slice-C2 页面合并后该导航项消失 → 停在错误页面 → 后续焦点断言连带红（当时误判为 P1-4 红）。
  已改为回退链：`all` 导航 → `memory` 导航 → `location.hash='#memory'`，新旧结构双兼容。
- **快照基线会烘焙他人在制前端**：`route-snapshot.json` 的 `/`、`/app.js` 静态哈希来自磁盘现状，
  本批重定后含 Slice-C2 未提交内容——**对方收口提交时需重跑 `npm run snapshot`**。
- **诊断门禁红先看失败项符号**：PowerShell 管道 GBK 会把 ✗ 显示成乱码，需
  `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 后重跑，否则会把绿项当成红项排查。
