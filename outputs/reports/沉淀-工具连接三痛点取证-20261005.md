# 沉淀：MemoryOS「工具连接」三痛点定点取证（2026-10-05）

## 核心结论
1. 扫描漏新智能体：四层发现全靠硬编码清单+窄指纹（scan.js:172/188/204/294-296），「已安装」层靠 AI_NAME_RE(336)+别名表(339)；新 IDE 无载体文件、目录名不含关键词、CLI 不在 PATH、快装后 60s TTL（reg-plans.js:311-312）内复扫都必漏。
2. 配置内容不对：片段生成器（scan.js:494-534）只注入 MEMORY_AGENT/MEMORY_DB，不含 EMBED_*、MEMORY_AGENT_FPATH、MEMORY_TOKEN；generic 片段（528-533）连 MEMORY_AGENT 都没有 → 心跳落 unknown 被 plans.js:334 过滤；codex 片段产 `[[mcp_servers]]` 数组表而本机实配全用 `[mcp_servers.<name>]` 键表（C:\Users\WYX\.codex\config.toml 实证）。
3. applyConnectWrite（scan.js:600-633）对 JSON 载体尾部字符串拼接后整文件覆写，JSON 必坏；codex TOML 追加若落在文件末尾段后也会被并进错误的表上下文（本机 config.toml 末尾段是 [sandbox_workspace_write]）。
4. 真源一致：MEMORYOS_SERVER env 注入（core-process.js:64）与 scan.js:494 同源；MEMORY_DB 三处（core-process.js:60 / dashboard.js:309-311 / server.js:21-23 / scan.js:501）均为 %APPDATA%\MemoryOS\data\memory.db，一致；不一致点是 EMBED 口径（壳层 local+仓内 models，片段缺省→server.js:44 兜底 local、缓存落 ~/.cache/memoryos-embed 二次下载）。
