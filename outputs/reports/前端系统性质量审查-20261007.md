## 3. 风险与规避建议

| 编号 | 改动 | 可能引入的风险 | 规避方式（必须做） |
|---|---|---|---|
| H1 | 搜索并入分页 + 改委托 | ① 搜索后用户看不到"共 N 条"语义变化；② 委托依赖 `data-id`，若某行模板缺失该属性则点击失效 | 复用 `renderAllTable` 的 `#allCount` / `#allPageInfo` 文案逻辑；改完用现有 `outputs/a11y-ui-walk.mjs` / `ui:walk` 跑一遍点击链路；保留 `row-open` 的 `data-id`（主表格已验证） |
| H2 | 看板改事件委托 | 拖拽是**自研 Pointer Events**（`4072-4092`，注释指出 headless/CDP 下 `setPointerCapture` 不可靠）；改委托后若 `pointerdown` 目标判定写错，会导致**拖拽失效或误触发详情** | 拖拽状态提为模块级单例后，先补一条"拖后不触发详情"的回归断言（现有 `el.dataset.dragged` 逻辑必须原样保留）；用 `npm run ui:walk` 或 CDP 脚本验证拖放 |
| H3 | 卡片加 `role=button`/键盘操作 | 读屏会把每张卡读成"按钮"，卡片内的子元素语义被压平；`tabindex` 让 Tab 序列变长（百张卡 = 百次 Tab） | 卡片容器用 `role="button"` + 内层文本保持纯文本（现状已是）；若列内卡片多，采用**单 Tab 停靠 + 方向键在列内移动**（roving tabindex），不要在每张卡都塞 `tabindex=0` |
| H4 | 引入 ESLint / 扩 lint 范围 | 一次性开严格规则会对 8,625 行报上千错，团队被迫 `--no-verify` 或全量关规则 → 门禁形同虚设 | **分档落地**：先只开 `error` 级（no-undef/no-unused-vars/no-empty），其余设 `warn`；`lint-syntax.js` 扩范围**只加 `node --check`**（零误报），ESLint 单独一条 `lint:ui` 脚本，不阻塞既有 `npm test` |
| H5 | 拆分 `app.js` | **高风险**：单 IIFE 内 274 个声明互相引用，切文件时漏挂全局或加载顺序错 → 白屏；且本项目有多 AI 并行分区约定（`CLAIM.md`） | ① **先固化基线**（git 无上游时先备份整目录，项目记忆中已记录"工作区曾有 11 个 dist 文件未提交"的教训）；② 只做**机械搬移**：不重命名、不改逻辑、不改注册顺序；③ 每搬一个域跑一次 `npm run ui:walk` + 手工点查对应页面；④ 严格遵守 `CLAIM.md` 分区，改动前先读 |
| H6 | 图表读 CSS 变量 | `getComputedStyle` 取到的是**运行时**值，若脚本在 CSS 加载前执行会取空；主题切换瞬间可能读到中间态 | 在 `EChartsLoaded.ensure()` 成功后才读；缓存失效时机绑定主题切换事件（而非每次绘图都读）；取空时回退到现有硬编码值（保证不比现状差） |
| H7 | 1 s 轮询套 guard / 放宽到 2 s | 放宽后"设计拾取"实时感下降（该功能是 Chrome 实时拾取，用户预期即时） | **先只加 guard（零行为变更）**，放宽间隔需产品确认；且 `D.sig` 签名相同即跳过 `render()`，实际体感不变 |
| M1 | 统一 `apiGet` + 请求序号 | 给所有请求加超时可能打断**长任务**（如 ingest/扫描本来就要跑几十秒） | `AbortSignal.timeout` 对长任务路由**显式豁免**（`null`）；序号比对只加在"详情/评论/运行"这类可抢占场景 |
| M3 | 错误边界加过滤 | 过滤后**真实脚本错误**若被误判为资源错误则不再展示错误态 | 判据写严：`e instanceof ErrorEvent && e.filename` 才进全屏态；保留 `console.error` 全量输出，便于回溯 |
| M4/M5 | 清理 `!important` / 合并 5 套 token | **样式回归高风险**：`!important` 往往是为了压掉另一处更高特异性规则，删掉即串味；删旧 token 块可能让仅在那里定义的变量失效 | ① 按"改到哪清到哪"，不做全量清理；② 删 token 块前先用脚本枚举"仅在该块定义且被 `var()` 引用的变量"（已确认需保留 `--font-display/--font-body/--sidebar-w/--accent-purple`，并入 4009 块）；③ 每次清理后对比关键页面截图（概览/记忆/看板/暗色各一张） |
| M6 | 抽公共 view model | 两处 UI 目前**视觉不同**（一处卡片式、一处时间线式），强行统一可能丢失差异 | 只抽**数据变换**（状态映射/耗时/按钮判定），DOM 外壳各自保留；先补单测级断言（同一 step 输入 → 相同 view model） |
| M7 | echarts 实例复用 | `setOption` 默认 merge，旧 series 残留会导致"图表多出一条线" | 明确传 `{ notMerge: true }`（或对 series 数量变化的场景）；切页 `dispose` 前先确认该实例不再被 `resizeAllCharts` 引用 |
| M8 | 焦点陷阱 | 陷阱写错会**锁死键盘**（用户出不去），比没有陷阱更糟 | 必须保留 Esc 作为逃生口（现状已有），并在 `Tab` 循环时校验 `el.contains(document.activeElement)`，异常时直接放行 |
| M11 | 加 `defer` / 启用压缩 | `defer` 改变执行时机：若 HTML 中有依赖 `app.js` 已执行的内联脚本会报错 | 已确认 `index.html` 只有 `6070` 一个外链脚本、无内联 `<script>` 依赖，加 `defer` 安全；压缩属可选，回环场景收益小，建议仅在分发场景启用 |
