🔴 阻断级问题（功能/可视化不可用）5 项
P0-1
知识图谱渲染成无意义的正圆环，完全无法展示关系
知识图谱页

布局截图实证：200+ 节点被力导向布局均匀排成一个正圆形，节点小到没有文字标签，连线沿圆周/穿圆心，视觉上就是一个蓝色圆圈，看不出任何聚类、层级或关联。顶部还提示"图已截断（节点>200）"，等于默认状态就是坏的。

实测：进入页面默认即如此，图例有笔记/记忆/卡片三类，但只能看到蓝色笔记节点，图谱作为核心功能不可用。
修复方向：节点超阈值时默认按 scope 聚类折叠（而非硬截断后仍全量画圈）；节点按连接度做力导向权重而非均匀环形；默认深度收窄到可读范围并显示标签。
P0-2
任务看板节点严重重叠，卡片互相压住无法阅读
任务看板页

布局截图实证：右上角 #63 卡片直接压在 #51 卡片之上，两张卡的标题文字互相覆盖；与此同时左侧列与中间列之间却留着大片空白。自动排布算法既重叠又疏密悬殊。

实测：默认进入为 120% 缩放且未"适配全图"，一进来看到的是局部错乱画面而非整体。102 节点 / 61 连线。
修复方向：自动排布加入碰撞检测（节点间距≥卡片宽+gap）；进入页面默认执行一次"适配全图"；持久化坐标加载后做重叠校验。
P0-3
记忆总数三处数字互相矛盾（247 / 1855）
概览·全部记忆·设置·侧栏

数据截图实证：概览统计卡"记忆总量 247"、侧栏徽标 247，但"全部记忆"页右上角是"共 1855 条"、设置弹窗"关于"里"记忆总数 1855"。用户无法判断哪个是真的，严重损害数据可信度。

修复方向：统一统计口径（247 疑似 active 子集、1855 为全量含归档/合并），在卡片上明确标注口径，如"活跃记忆 247 / 全部 1855"，所有页面共用同一接口字段。
P0-4
侧栏"待归档·僵尸"徽标 18，实际列表只有 1 条
侧栏 vs 僵尸页

数据截图实证：侧栏红色徽标显示 18，点进去"全部僵尸"只有 1 条记录（闲置 44 天）。徽标计数与列表查询口径不一致，会让用户以为漏加载了。

修复方向：徽标计数与列表使用同一筛选条件（状态+闲置天数阈值），并在切换 15+/30+/60+ 天时同步。
P0-5
暗色主题下多个输入框仍是白底，亮到刺眼
新建记忆弹窗·笔记页

主题截图实证：暗色模式下，"新建记忆"弹窗的"项目 SCOPE"输入框、笔记页的 VAULT 路径框和 PROJECT 框都是纯白底白字场景，与深色弹窗强反差。根因是暗色覆盖选择器只写了 .form-field input，而这些输入框不在 .form-field 容器内。

修复方向：把暗色输入框样式选择器改为覆盖所有 input/textarea/select（或统一加 form-field 类），不要依赖父级 class。
🟠 严重问题（明显体验缺陷）9 项
P1-1
中英文混杂贯穿全应用，技术术语直接裸露
全局

国际化截图实证，同类元素一会儿中文一会儿英文：

· 类型标签：大部分页面是中文"经验/踩坑"，但全部记忆表格里 task 是纯灰文本无彩色标签，僵尸页 experience 是英文紫标签。

· 图表：折线图图例写 write / returned / cited，图内标注却是"写入/返回/引用"；环形图类型 task 夹在中文里。

· 审计日志操作名全英文 decay · eff_update / trial · promote；采集页类型列 rule/memory/convo；说明文字裸露 scope/frontmatter/dry-run/INGEST_MAX_CALLS/127.0.0.1:18900。

修复方向：建立类型/状态/操作的中英文映射字典，展示层统一中文化（英文原值放 title 提示）；面向用户的描述句移除环境变量、IP、字段名。
P1-2
空状态大面积留白且无引导，用户分不清"没数据"还是"加载失败"
仲裁队列·Agent·笔记

空状态截图实证：仲裁队列"待裁决 0 条"时只剩一个空表头和整屏空白，没有图标/说明/操作入口；Agent 页对话区空着，建议问题"试着问…"只是纯文本不可点击；笔记页三个空栏各自重复提示"选好 vault 再导入"，却不解释 vault 是什么。

修复方向：统一空状态组件（图标+一句话说明+主动作按钮）；Agent 建议问题做成可点击 chips 直接发送。
P1-3
设置弹窗内容溢出底部被截断，快捷键文字竖排
设置弹窗

布局截图实证：弹窗 max-height 80vh 但内容更高，LLM 配置/系统区只露出半截（"采集/提炼/+内…"被切），且没有明显滚动提示。快捷键卡片里"聚焦搜索""详情切换"被挤成一字一行的竖排文字。

修复方向：弹窗 body 设 overflow-y:auto 并让 footer 固定；快捷键标签加 white-space:nowrap，栅格给足最小宽度。
P1-4
趋势图 X 轴时间不连续却等宽排列，造成趋势误导
趋势页

图表截图实证：周增量柱状图 X 轴为 W19/W23/W31/W36/W37/W38，中间跳过数十周，但相邻柱间距完全相等，W19→W23（4周）与 W36→W37（1周）视觉等宽；前段大量空周位留白。eff 衰减曲线 X 轴用 #1 #113 #225…#1233 记忆序号，用户无法理解含义。

修复方向：时间轴按真实时间比例或只显示有数据的周；衰减曲线 X 轴改为"记忆年龄/天数"并加轴标题。
P1-5
eff 质量直方图中段断裂、写入热力图无坐标标签
概览页

图表截图实证：eff 直方图在 0.1~0.3 区间完全无柱，形成视觉断档却未说明；写入活跃度热力图几乎全空，且没有行（星期）列（日期）标签，只有"少→多"图例，无法解读哪个格子对应哪天。

修复方向：空区间补 0 值占位并保持连续；热力图补星期/月份坐标，无数据时给出空状态说明。
P1-6
全部记忆表格信息密度与可读性问题集中
全部记忆页

布局截图实证：内容两行截断且常断在词/句中间；EFF 列标题是缩写无解释；操作列两个图标按钮无文字/无 tooltip 区分；"指向的库"列在工具页大面积显示"无法判定/—"，信息价值低；类型筛选无计数而类别筛选有计数，不一致。

修复方向：表头加中文全称+tooltip；行操作按钮加 title/文字；空值率高的列默认收起到"更多列"。
P1-7
亮色主题背景色与设计变量不一致（米黄 vs 冷蓝灰两套底色）
全局 · index.html L14/L307

代码变量声明是"米白 #FCF9E8"，但 body 实际背景是冷蓝灰渐变 #f8fafc→#e8f4f8；背景光晕还用了金黄 #fccd4d 和玫红 #e11d48，与青色主色不搭，亮色下尤其突兀。

修复方向：统一底色变量与 body 渐变；光晕/星点改为青色系同色系。
P1-8
992–768px 区间侧栏被锁死，汉堡按钮未显示
响应式 · L2257/L2333

响应式侧栏在 ≤992px 自动收成 64px 图标条，但展开/收起按钮 .sidebar-toggle 默认 display:none，要到 ≤768px 才显示。768–992px 之间用户无法手动展开侧栏。

修复方向：把 toggle 显示断点提前到 992px。
P1-9
暗色模式下强调按钮/轨道对比失衡
概览·状态分布

主题截图实证：暗色下"去写入一条记忆"仍是高饱和亮黄块，在深色背景上刺眼、与青色体系脱节；状态分布的灰色轨道条几乎与背景融为一体，只剩彩色填充段。

修复方向：警告色在暗色下降饱和/提亮文字；轨道色用 rgba(255,255,255,.08) 保证可见。
🔵 一般问题（一致性与打磨）11 项
P2-1
CSS 变量 --radius 未定义，骨架屏圆角失效
L661

代码.skeleton-card{border-radius:var(--radius)}，但只定义了 --radius-lg/md/sm，导致加载骨架直角，与正式卡片 20px 圆角不一致。改为 var(--radius-lg) 即可。

P2-2
硬编码颜色 469 处、内联样式 330 处，主题维护脆弱
全局

代码142 处 hex + 327 处 rgba 写死，暗色靠逐元素 [data-theme=dark] 覆盖（这正是 P0-5 漏网的根因）；330 个内联 style 让统一样式和响应式很难收敛。建议色值全部变量化、重复内联提取为类。

P2-3
"记忆利用率健康"数字斜杠堆叠难读
概览页

布局截图实证：第三个指标 153/1234/1039/36 一串斜杠挤在一格，标题只写"30天 搜/写/回/引"，读者要逐位对应。建议拆成 4 个小数字或用"搜153·写1234·回1039·引36"带标签排列。

P2-4
高价值 TOP 榜：排名色区分弱、指标名用英文大写
高价值TOP页

国际化第 1/2/3 名色块（黄/灰/棕）区分度低，第 4 名起突然无底色；右侧 CITED / RETURNED 全大写英文，两栏内容大量重复却未说明区别，顶部说明也是 raw-cited+inferred-cited。建议中文化指标名、明确两栏定义。

P2-5
跨工具页用纯数字列表表达矩阵，缺少视觉编码
跨工具页

图表名为"Writer×Reader 复用矩阵"，实际是纵向列表 + 右侧纯数字，数值大小无法一眼比较，(returned)/(cited) 全英文。建议加内联条形（按次数比例）或真正的二维热力矩阵。

P2-6
扫描进度条完成后仍满格常驻，无完成态
工具连接页

状态扫描已 100% 完成，青紫渐变进度条仍一直满格显示，应在完成后收起或变为"✓ 已完成 N 个"静态状态，避免用户以为还在跑。

P2-7
导航 <a> 无 href、图标按钮缺 aria-label
侧栏·顶栏

可访问性导航项是无 href 的 <a>，键盘/屏幕阅读器不友好；主题🌙、设置⚙️只有 title 无 aria-label（任务地图缩放按钮反而做对了）。建议补 href hash 或改 button，并统一 aria-label。

P2-8
字体走外部 CDN，离线静默回退
L10

性能Space Grotesk 等从 miaoda.feishu.cn 加载，桌面端离线时数字/标题字体静默回退系统字体，版式跳动。建议 woff2 本地化打包。

P2-9
常驻动画过多，hover 上浮过度普遍
全局

性能双 orb 浮动 + 星点闪烁 + 卡片 stagger 入场 + ripple + shimmer 同时运行；几乎所有卡片 hover 都 translateY 上浮，鼠标划过时画面持续晃动。建议页面不可见时暂停背景动画，数据卡去掉位移只留描边反馈。

P2-10
UI 版本号硬编码两处，任务地图高度写死视口值
L2551/L2651 · L1507

代码"UI 09-11 23:36"在 logo 和顶栏各硬编码一份，易不一致；任务画布 height:calc(100vh - 285px) 靠魔数估算，顶栏一变就溢出/留白。建议版本由 JS 注入、画布改 flex 自适应。

P2-11
z-index 层级与顶栏小屏挤压缺少统一管理
全局

代码z-index 从 0/50/100/200/400/500/999 散落各处无变量；顶栏 actions 无 flex-wrap，窄屏搜索框+多按钮易挤溢。建议 z-index 变量化、顶栏允许换行或按断点收按钮。

📋 修复优先级建议

第一批（数据可信 + 核心可视化）：P0-3/P0-4 统一计数口径 → P0-1 图谱聚类 → P0-2 看板防重叠 → P0-5 暗色输入框。这批直接决定"数据能不能信、核心页面能不能看"。

第二批（一致性 + 可用性）：P1-1 术语中文化映射、P1-2 空状态组件、P1-3 设置弹窗、P1-4/P1-5 图表坐标与断档、P1-6 表格可读性。

第三批（主题/响应式/打磨）：P1-7~P1-9 主题与响应式，P2 全部纳入一次"设计系统收敛"：色值变量化、去硬编码、字体本地化、动画降噪。
