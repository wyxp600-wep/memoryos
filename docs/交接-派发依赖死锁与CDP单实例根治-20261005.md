### 2.2 CDP 驾驶「端口 25s 未就绪」（VS Code 全链路实测失败的真因）

- **表象**：派发后 `[驾驶] CDP 调试端口 9329 未就绪（等待 25s）——应用可能不支持 --remote-debugging-port 或启动过慢` → run `failed`。
- **真根因（只读取证坐实）**：**VS Code 是单实例应用**——第二个进程把 `--remote-debugging-port` 交给已有实例后**直接退出**，参数只对第一个实例生效。
  - 证据：已有 Code.exe 主进程 `PID 23500 @14:10:18` **不带**该参数；18 个 Code.exe 里带该参数的 **0 个**；9329 **无监听**；`%APPDATA%\Code\DevToolsActivePort` 内容 `9329`、mtime 14:56:44（正是派发那一刻）**却无监听**。
  - 顺带纠正一个误判：**登录态没问题**（`%APPDATA%\Code` 里 token 有效），失败发生在更前面的连接阶段。
- **根治（B 方案，改 `dist/dashboard-reg-cdpexec.js`，已实施、待提交）**：
  1. **前置① 复用**：拉起前读 `DevToolsActivePort`（`--user-data-dir` 优先，否则按 exe 取平台默认：`code.exe→%APPDATA%\Code`、`chrome.exe→%LOCALAPPDATA%\Google\Chrome\User Data`），`/json/list` **实测通**才复用（文件可能是残留，必须实测）→ 直接接进已有实例、不再拉第二个进程。复用时 `job.pid=null`，收口 `killTree` 早退，**不杀用户窗口**。
  2. **前置② 诊断**：等不到端口时，异步 `Get-CimInstance Win32_Process` 查同名 exe 还有哪些进程（**4s 兜底超时**，不许挂住启动链），有则报**可行动错误**，无则回落原文案：
     > `Code.exe 已在运行但未开调试端口（PID …）——单实例应用会把 --remote-debugging-port 交给已有实例后直接退出，端口因此永远不会就绪。请先完全退出 Code.exe（含托盘图标），再重新派发`
  - **被否决的方案**：C=独立 `--user-data-dir`（**丢登录态**，且已拍板不自动化登录）；D=驱动先杀已有 VS Code（**丢用户未保存编辑**）。
