# 正文：通用任务协作规则 v3.0

## 一、文档定位与版本历史

本文件是所有智能体必须遵守的唯一协作约定，适用于 Trae、WorkBuddy、Codex、Claude、zcode、dsh。本文为最终完整版，保留 v1.1、v1.2、v1.3 的机制、标识与历史版本关系，不删除、不压缩掉独立条目。 `✅已实现`（作为约定文件本身）

### 1.1 版本演进

- **v1.1 效率版**：解决空转、重复轮询、写放大。核心是工作流包、租约心跳、首进展承诺、只读并行写串行、完成模板自动对账。
- **v1.2 质量版**：解决交付虚、不可复现、验收弱。核心是 DoD 2.0、证据矩阵、分级验收、反例边界、知识沉淀、质量门禁、返工根因。
- **v1.3 防错版**：解决误操作、脏写、不可逆事故。核心是前置检查、幂等 + fencing、红线硬阻断、五步防错、审计链、双写一致性、故障预演。
- **v2.0 融合版**：将效率、质量、防错三包合并为统一规则。
- **v3.0 多智能体一致性增强版**：增加强一致/顺序一致/最终一致分级、MACP 协议字段、单写者、资源锁、fencing、脑裂处理、三方对账、冲突裁决。
- **v3.0 完整版**：即本文。保留前序所有版本机制与标识，作为现行统一规则。

### 1.2 优先级

- 与客户端私有规则冲突时，以本规则为准。 `✅已实现`
- 与 MemoryOS 已有约束冲突时，以 #4158 任务标签、#4001 状态机、#4186 统一入口、#4000 验收证据链为准。 `✅已实现`（4 条约束均已在库）
- MemoryOS MCP 任务池为唯一事实源（SSOT）；看板为只读投影；WorkBuddy MEMORY.md 为镜像。 `⚠️部分实现`（SSOT 成立；但 MEMORY.md 镜像当前超限被截断，且看板 done 投影缺失，见 A.3）

## 二、总则与核心原则

1. **唯一入口**：所有任务一律进 MemoryOS MCP 任务池，禁止在各自客户端私有任务区建任务。 `✅已实现`（#4186）
2. **实证闭环**：完成必须有 build、curl、单测、看板对账等日志，禁止 should、probably、大概。 `⚠️部分实现`（工具层无强制门禁，靠 agent 自律）
3. **单写者**：单任务单 owner，单资源单 writer。 `⚠️部分实现`（任务侧有 `assignee` + `claim_lock`；资源侧无锁表）
4. **幂等与可重放**：所有关键写操作带幂等键，重复请求返回首次结果。 `❌待实现`（无 `idempotency_key` 字段）
5. **可审计**：认领、迁移、完成、回退、审批全程留痕。 `✅已实现`（`memory_events` 662 条 + `card_events`）
6. **可回滚**：不可逆操作必须降级为可回滚操作，回滚脚本必须实际验证。 `✅已实现`（约定层；工具层无强制）
7. **前后端一致**：任务池、看板、记忆库三方一致才算闭环。 `❌待实现`（实测 done 投影为 0，见 A.3）
8. **版本保留**：v1.1、v1.2、v1.3 作为历史版本保留，v3.0 为现行统一版。 `✅已实现`（本文件）

## 三、术语与角色

- **SSOT**：单一事实源，即 MemoryOS MCP 任务池。 `✅`
- **投影**：看板，只读，最终一致。 `⚠️`（当前 done 投影缺失）
- **镜像**：WorkBuddy MEMORY.md，从属于 MemoryOS。 `⚠️`（当前超限截断）
- **Agent**：执行任务的智能体。 `✅`
- **Owner**：当前任务唯一认领者。 `✅`（`cards.assignee`）
- **协调者**：冲突裁决者，只能基于 SSOT 裁决，不得私建任务、不得绕开任务池。 `✅`（约定层）
- **Epoch**：任务重开产生的新代际。 `❌待实现`
- **Version**：只增版本号，防基于旧状态写。 `❌待实现`
- **Lease**：租约，认领后有效时间。 `⚠️部分实现`（`cards.lease_expires_at`；实为 30 分钟，非本文 10 分钟）
- **Fencing Token**：租约续期/释放时递增，旧 owner 恢复后因 token 低被拒绝写。 `❌待实现`
- **Idempotency Key**：`task_id + step + input_hash`，用于去重。 `❌待实现`
- **Causal Parent**：因果父节点，支持重放与审计。 `❌待实现`
- **DAG**：依赖有向无环图，禁止循环依赖。 `✅已实现`（`task_assign.depends_on`；19 条任务已用）
- **DoD**：完成定义。 `✅`（约定层）
- **证据矩阵**：完成时附带的证据字段集合。 `✅`（由 `task_done.conclusion` 承载）
- **dependency_blocked**：依赖阻塞。 `⚔️`（#4001 未定义此态）
- **blocked**：执行阻塞。 `✅已实现`（#4001 已定义）

## 五、任务创建与依赖

### 5.1 必填字段

scope/project、标题、content、优先级、依赖、创建者、验收标准/DoD、标签。

`⚠️部分实现`：`task_assign` 入参仅 `content` / `assignee` / `depends_on` / `project`。
**标题、优先级、创建者、DoD 需由 agent 自行写进 `content` 正文**（无独立结构化字段）→ 建议在 content 内固定使用
`【目标】【验收标准】【依赖】【优先级】` 四段式，以实现机器可解析。

### 5.2 依赖规则

- 依赖必须是 DAG，禁止循环依赖。 `⚠️`（`task_assign` 不校验环，需 agent 自律）
- 依赖未全部 `done` 时，任务为 `dependency_blocked`，不可认领。 `✅已实现`（`task_next` 按依赖拓扑算入度=0 集）
- 依赖变更 → 下游标 `dependency_stale`，重新评估，不自动开工。 `❌待实现`
- 上游 `done` 只把下游置回 `pending`，不直接置 `in_progress`。 `✅已实现`

### 5.3 优先级

- 建议枚举：P0、P1、P2。 `✅`（写进 content）
- 同一 agent 同一时刻只做 1 个主任务。 `✅`（约定层）
- 默认不抢占，按优先级排队。 `✅`（`task_claim` 无抢占语义）

### 5.4 取消、失败、重开

- 取消：→ `cancelled`，写原因与证据。 `⚠️`（无 `task_cancel` 工具，需 SQL/接口）
- 失败：→ `failed`，写原因、影响、证据。 `⚠️`（同上；实测 0 条使用）
- 重开：`task_reopen` 生成新 `epoch`，保留旧结论。 `❌待实现`
- 返工任务必须关联原任务，写根因与防复发措施。 `✅`（写进 content）

- 交接必须写清 `next_action`、owner、上下文、风险、未完成项。 `✅`
