## 2. 为什么值得做（背景）

多智能体协作以前是“队列领单”单通道：没装 MemoryOS 工具的智能体参与不了，装了配置也管不着它用什么模型、什么工作区，干完活下个智能体也接不上上下文。这套画布把“派活”变成看得见的连线，把“干活的智能体”变成可配置可直播的卡片，把“交接”变成自动落卡的前情提要——一条完整的价值链。

## 3. 现在的系统是什么样（验收基线）

- 画布上：建卡/改型/自造类型/拖动/连线/删除全通；50+ 张卡、15+ 条边渲染流畅（数据不变时轮询零重渲染）。
- 派发三条通道按智能体卡配置自动分流；**派发边可审计**（每边锚定工作证，换代自动翻状态）。
- 交接卡只在成功收口时生成（失败不产卡，防看板被失败任务淹没）；内容分节详述。
- 智能体卡上两个实时窗口：“⌨ 日志”（终端输出流）和“📺 直播”（桌面软件画面帧流）。
- 所有验证入口：隔离库端到端 39 项、路由快照门禁 245 条、聚合冒烟 23 项、语法 lint 87 文件——**全绿**。

## 5. 怎么上手（两分钟）

1. 打开看板（浏览器已开就刷新）→ 顶部“任务看板”页签 → 工具条“**节点画布**”按钮。
2. 左边“＋ 卡片”拖到画布 → 卡片上点类型徽标改型 → 点“⌨ 日志”/“📺 直播”/“派发 ⟶”按钮体验各能力。
3. 建智能体卡：任卡改型为“智能体” → 配置向导里选智能体（下拉是真实扫描到的清单）、通道、工作区、模型。
4. 派活：任务卡的“派发 ⟶”点住后点目标智能体卡 → 弹层确认。

## 6.2 代码地图（谁负责什么）

**数据层（db.js SCHEMA 段尾部，全部“只增不改”，回滚 = drop 表）**
- `card_types`：卡片类型注册表。内置四种子 task/agent/handoff/doc + 四个端口行为档位（can_dispatch_out/in、can_inject_out/in）——**连线合法性由档位判定**，自定义类型默认全 0（纯文档节点）。
- `agent_profiles`：智能体纯配置实体（无位置无状态）。channel ∈ {queue, cli, cdp}（**没有 uia 档**，UIA 只是 CDP 的内部兜底，失败直接降档“手动粘贴”）。
- `card_edges`：用户可编辑的边（kind ∈ dispatch|inject）。dispatch 边锚定 dispatches.id；**status 是纯投影字段**（真源在 dispatches 表），边表永不参与对账裁决。两个部分唯一索引保证幂等连线。
- `cards.kind` 扩了取值：'agent'（投影卡，meta.profile_id 指向档案）、'handoff'（纯文档卡）。图对账排除清单含这两者。

**后端（resources/memoryos/dist/，ESM，即“源码”本体）**
- `dashboard-reg-cards.js`：类型 CRUD / retype 改型 / agent-profiles CRUD / card-edges / 智能体卡状态端点；dispatch-agent 的连线边事务 + **三通道分流**（channel 计算必须早于 message 构建——channel 被提示词引用，踩过 TDZ 坑）；finalizeCardDispatch 的边状态翻转 + 交接卡生成（**仅成功收口**，body 为详版分节模板）。
- `dashboard-reg-cliexec.js`：CLI 直控执行器。串行队列（concurrency 默认 1，pump 计数在循环内递增）、60s 心跳续租（renewCardLease 单点）、stdin 传提示词、全量输出独立累积（fullText，SSE 缓冲可截但解析/落盘用全量）、分隔符协议 `<<<HANDOFF>>>` 收口、14 天日志轮转、收口修剪（终态 job 只留 20 条）。
- `dashboard-reg-cdpexec.js`：CDP 驾驶执行器。带 `--remote-debugging-port`（9300 起）拉起桌面 App → CDP WebSocket（Node≥22 内置，零新依赖）→ screencast jpeg 帧流 SSE；注入失败**不重试不死磕**（D10）；未进入 driving 就失败的会话自动杀掉自拉 App（防泄漏）；WS 断开即收口（防租约无限续命）；会话 2h 上限；扫描 60s TTL 缓存。
- `dashboard-exec-util.js`：共享骨架（killTree/safeJson/pruneFinishedJobs/findJobByCard/streamJobSSE）。**刻意不做**基类合并 finish 流程（两执行器 finish 差异是实质的，合并只加间接层）。
- `dashboard-reg-knowledge.js`：派发 run 租约心跳（60s 定时器，必须定义在执行 handler 作用域内再调用——踩过跨作用域调用 bug）；dispatchRuns 满了删最旧不 clear()。
- `db.js`：`renewCardLease`（卡片租约+工作证续期 SQL 单点，三处调用）。
- `dashboard-reg-static.js`：静态白名单——**新增前端文件必须在这里加路由**（canvas-editor.js 曾 404）。

**前端（resources/memoryos/memoryos-dashboard-redesign/）**

## 6.4 已知坑（踩过，别再踩）

1. **Windows 上 npm shim（codex.cmd 等）裸 spawn 必 ENOENT**，且 .cmd 直接 spawn 被 Node 安全策略禁 → CLI 执行器用 `shell:true` + 预引号整串（node 外层引号被 cmd /s 剥掉，内层引号保留）。
2. **`C:\Program Files` 带空格路径** + shell:true 时所有 token 预引号。测试脚本 `-e` 内嵌引号会与 cmd 引号规则纠缠 → fake CLI 落盘为文件最稳。
3. **scanAgents() 返回 `{agents,total,connected}` 对象不是数组**，直接 .map 会静默失败（graph 的 profileMissing 就因此静默失效过一次）。
4. **跨作用域引用 try 块局部变量**（`r.answer`、`startRunHeartbeat`）会被 catch 静默吞掉 → 症状是“run 完成了但卡不收口”；修法一律 try 外声明变量承接。
5. **async 函数裸调用**（start(job) 不接 catch）= unhandled rejection 崩整个 dashboard。
6. **静态服务是白名单制**，新前端文件不加路由就 404。
7. **终端显示 GBK 乱码≠数据错**：curl 输出中文乱码是本机终端问题，用 node 读 API 验证真实编码。
8. **graph 每次请求跑载体扫描很慢**——已加 60s TTL 缓存（cards 域）与 cdpexec 自身缓存；新代码不要裸调 scanAgents。
9. **删 .bak/旧文件前先核对创建时间**（本次误删过 4 个旧会话备份，影响低但属失误）。
10. **手改 AGENTS.md 会被同步覆盖**；门禁抖动 exit=13 原样重跑勿误判。
