## 2. 目标形态与核心契约

```
现状:  REST 路由 ─┐                        ┌─ 各自实现领域逻辑（写两遍）
                   ├─→ 业务逻辑（重复）  ─┤
       MCP 工具  ─┘                        └─ 各自包装输出（协议各不相同）

目标:  REST 路由 ─┐                        ┌─ operation 注册表（唯一）
                   ├─→ 薄适配 ─→ invokeOp ─┤   name / domain / kind / risk
       MCP 工具  ─┘                        └─ inputSchema / handler / transports
                                             └─→ 领域逻辑（**只有一份**）
```

**handler 契约（本层核心，不可动摇）**：`handler: (ctx, args) => result`，返回**裸领域值**——
不含 MCP 形 `{content}`/文案、不含 HTTP 状态码/`{ok}` 信封。协议包装由各适配器负责。

**risk 口径**：复用 `exec-tools.js::TOOL_RISK`（**不另造枚举**），取不到按既有 fail-closed 回落 `L4/required` 并在 `risk.source` 注明。

**同名重复注册 → 直接 throw**：静默覆盖会让"同名两条各写一份逻辑"重新长回来，这正是要根治的病灶。

### 7.1 ★ 核心结论：`POST /api/memory` ↔ MCP `memory_write` **非同源**（推翻 §1 的初判）

原 §1 把这一对列为"真重复取证"，逐条复核后**不成立** —— 两者 7 处实质差异：

| # | 维度 | REST `POST /api/memory` | MCP `memory_write` |
|---|---|---|---|
| ① | 写入者身份 | 恒 `human:dashboard` | `agentName()` / `agentFpath()`（**调用时**解析） |
| ② | 去重闸门 | **无**（同文重复即落两条） | 幂等键 / 精确同文 / 事务内全量向量比对（三闸；命中 merge + `bumpConfidence` + `foldInto`） |
| ③ | 修订链 | **无** | `supersedes` + `version` 乐观栅 + `source_task_id` 因果链（旧条归档 `archived`） |
| ④ | 入参面 | 收 `sector` / `sensitivity` 并按枚举校验（非法 → 400） | 不收（走 db 缺省推导） |
| ⑤ | 审计落点 | `logUsage` + `logDaemon`（`manual-write` 留痕） | `logUsage` + `stateReceipt` |
| ⑥ | 特殊分支 | 无 | `[task]` 状态头 ⇒ **强制 type='task'** + 提示走 `task_assign` |
| ⑦ | 输出形态 | `{ ok, id }` | 中文回执 + `stateReceipt` + 写前检索硬门禁提示 |

⇒ **只迁 REST 一侧**，`server-reg-memory.js` 零改动；该判定已写成冒烟断言
「**无任何 op 声明 `mcp=memory_write`**」，防日后被"顺手统一"回去。
同理 `DELETE /api/memory/:id` ↔ MCP `memory_feedback` 也非同源（门禁/状态前置校验/审计文案不同），
且两者共享的部分本就是 db.js 的**同一个 `rejectMemory` 入口** —— 无重复实现可消。
