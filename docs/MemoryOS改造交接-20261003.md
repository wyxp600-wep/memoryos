## 2. 为什么值得做（背景）

以前多 AI 同时干活时，有三个说不清：

1. **谁说了算**：一个活几个人都在改，没人能判定「现在该听谁的」。
2. **被顶掉的人不知道**：活被别人接走，原来那个人可能还在闷头写，写完才发现白干。
3. **没人就当你放弃了**：AI 会话一断，卡住的活会被当成「不要了」自动清掉——其实人可能只是掉线了。

Orca 的三条规矩正好治这三件事：**权威只认「当前那一次尝试」**、**只有拿到正面退出证明才能放弃/重试**、**「人不在」不构成销毁授权**。

## 3. 现在的系统是什么样（验收基线）

- 一个任务同一时刻**只有一个权威**（数据库层面硬保证，不是靠自觉）。
- 被顶掉的人**会被主动告知**（心跳回执）。
- 卡住的活**只标不收**，取回必须走两条正经通道：人工放回，或满足条件后的半自动接管（需写权限）。
- 结论性动作（领活、收活、心跳、接管等）**支持重发不重复生效**。
- 内容被截断、检索降级，**都会显式告知**，不再静默。
- 分区表带状态列，**查不清的区强制只读**。
- 规矩的「提醒 / 强制」目前是**提醒档**，强制档已预留开关。

## 4. 你要做的两个决定

| 决定 | 说明 | 建议 |
|---|---|---|
| 要不要从「提醒档」升级成「强制档」 | 现在没凭据只提醒不拦；强制档会让没凭据的写入直接被拒 | **先保持提醒档**。判据已写死：等真出现「释放后仍被旧持有者写入且没被拦住」的实际案例，再升档。凭感觉升档会打断正常使用 |
| 工作区里别人未提交的东西怎么办 | 有两处代码改动、一处删除、一堆未跟踪文件，都不是本次改造的产物 | **先不动**，等那些东西的主人收口；只在文档里登记清单（见 5.4） |

## 5.2 关键概念与代码位置

- **dispatch（一次权威尝试）**：`dispatches` 表 + 局部唯一索引 `idx_dispatches_active` 机器保证「一任务同时只有一个 active」。读写函数在 `dist/db.js`：`readDispatchByKey` / `readActiveDispatch` / `createDispatch`（generation 取历史 MAX+1）/ `settleDispatch`。
- **四项权威判据**（与 `task_done` 硬校验同源）：① key 可解析 ② memory_id 相符 ③ state='active' ④ agent 相符。
- **软模式提示**：`dist/server-reg-task.js` 的 `softDispatchNotice()`（A1），六处写入点：heartbeat / release / block / reopen / verify / supersede。
- **fenced 位**：同文件 `fencedLine()`（A3），heartbeat 三处非拒绝回执用 `const tail = fence || dspNotice;`（fenced 优先，避免与 A1 重复播报）。无票时按 `(memory_id, agent)` 取 MAX(generation) 回退定位。
- **只标不回收**：`dist/daemon.js` 的 `reapExpiredLeases` 阶段二（B1）——打 `cards.lease_stale_at` + dispatch 置 stale，**不改头、不清锁、不放回**。
- **取回双通道**（G2 结论）：① 人工 `task_release`（唯一「放回可领」的正向动作）；② 半自动 `task_claim(takeover=true)`（前提：无 active dispatch **且** 存在 stale dispatch，须 scope ≥ write 凭据）。可发现性由 `task_next` 的 stale 段承担。
- **幂等重放**：`request_receipts` 表 + `readRequestReceipt`/`saveRequestReceipt`（D1），在 `server-reg-task.js` 单点包裹写类工具。
- **分区 state 化**：`CLAIM.md` §1 增 `state = active / released / unverifiable`；`unverifiable` = 强制只读。

## 5.5 已知坑（踩过，别再踩）

| 坑 | 现象 | 正解 |
|---|---|---|
| 结构化回执被污染 | 提示文本直接拼在 `⟨state⟩` JSON 同一行 → 解析失败（p26-lifecycle I2 断言红） | 所有追加文本**自带前导换行**，独立成行 |
| 长文件读不了 | `CLAIM.md`(77KB)、`db.js`(103KB)、`server-reg-task.js`(88KB) 直接读报超限 | 用 `offset`/`limit` 分段读，或 PowerShell 截断打印 |
| 编辑被拒 | 直接编辑 `C:\Users\WYX\Desktop\MemoryOS\...` 报 `Access denied`（限工作目录） | 走 5.4 副本流程 |
| 提交静默失败 | `git commit -F` 在含中文的路径下 `exit=1` 且零输出 | 提交信息文件写到 `.git/` 下（ASCII 路径） |
| 钩子输出被吞 | Shell 工具拿不到 git/hook 输出，误判成门禁失败 | 重定向到文件再读；门禁可三步单独复跑定位 |
| 门禁抖动 | `npm test` 中 mcp/p26-lifecycle 偶发 `exit=13` 且耗时异常（>10s） | 属间歇抖动，**原样重跑**，全绿再提交 |
