## 三、缺陷：Fastify 前缀提升未处理（4 条）

`printRoutes({ commonPrefix: false })` 会把**兄弟段的公共前缀提升到父节点**，子节点只打印**后缀且不带前导 `/`**。此时正确拼接是**纯字符串相接** `parent + seg`，而解析器（`:98-102`）无条件插入 `/`：

```js
const clean = seg.replace(/^\/+/, "");
full = parent === "/" ? `/${clean}` : `${parent}/${clean}`;   // ← 硬插 "/"
```

### 原始树实证（行号为 `printRoutes` 输出行）

```
40 "    ├── api/task (POST)"
41 "    │   └── s (GET, HEAD)"             ← 真实 /api/tasks

56 "    ├── api/rules (GET, HEAD)"
57 "    │   ├── /sync (POST)"
58 "    │   │   └── -targets (GET, HEAD)"  ← 真实 /api/rules/sync-targets

20 "    │       ├── /claim (POST)"
21 "    │       ├── /comment (POST)"
22 "    │       │   └── s (GET, HEAD)"     ← 真实 /api/cards/:id/comments

47 "    ├── api/agent/:id/connect (POST)"
48 "    │   └── -guide (GET, HEAD)"        ← 真实 /api/agent/:id/connect-guide
```

### 误拼全集（`buggy !== correct` 精确筛选，共 4 条）

| 解析器输出 | 真实路径 | 方法 | 后果 |
|---|---|---|---|
| `/api/task/s` | **`/api/tasks`** | GET, HEAD | **任务池核心路由未覆盖**；快照记 status=**404** |
| `/api/rules/sync/-targets` | `/api/rules/sync-targets` | GET, HEAD | 未覆盖；快照记 status=**404** |
| `/api/cards/:id/comment/s` | `/api/cards/:id/comments` | GET, HEAD | 未覆盖（且落入 `skipped.dynamic`） |
| `/api/agent/:id/connect/-guide` | `/api/agent/:id/connect-guide` | GET, HEAD | 未覆盖（且落入 `skipped.dynamic`） |

**幻影 404 佐证**：快照中 `/api/task/s` 与 `/api/rules/sync/-targets` 的 `status=404, contentLength=9, contentType=text/html` —— 即门禁实际请求了一个不存在的路径，并把它当作「已覆盖」。

## 四、覆盖率实测

用修正拼接逻辑重算路由真值集：

| 口径 | 数量 |
|---|---|
| 路径总数（去重） | **87** |
| 方法级入口总数 | **145**（= 工具报告的「发现 145 条」） |
| 含 GET 且无参（可快照） | 40 |
| 含 GET 但有动态段 | 5 |
| 仅非 GET（POST/PUT/DELETE） | **42** |

- 快照 40 条中 **2 条为幻影 404** → 有效覆盖 **38 / 87 = 43.7%**（路径级）
- **42 条仅非 GET 路径零覆盖**，含全部变更端点：`POST /api/cards/:id/claim`、`POST /api/cards/:id/status`、`POST /api/memory`、`POST /api/cards/apply-plan`、`DELETE /api/cards/:id`、`POST /api/ingest/run`、`POST /api/obsidian/import` …
- 5 条动态段 GET 零覆盖（其中 2 条因误拼而根本未识别为动态段）

**注**：原计划文档称「96 条路由」，实测为 **87 路径 / 145 方法入口** —— 口径差异来自「路径级 vs 方法级」，建议统一为「87 路径」。

## 五、修复建议（最小改动）

### 必修 1：拼接规则区分「后缀延续」与「新段」（改 2 行，`snapshot-routes.js:96-102`）

```js
if (seg === "/") full = "/";
else if (parent === "/") full = `/${seg.replace(/^\/+/, "")}`;
else if (seg.startsWith("/")) full = `${parent}/${seg.replace(/^\/+/, "")}`;
else full = `${parent}${seg}`;          // ← 前缀提升：后缀延续，纯相接
```

### 必修 2：把「已覆盖」与「404」解耦

对 `status === 404` 的快照条目应**直接判失败**（门禁不应把 404 记为覆盖）。当前若误拼路径保持 404 不变，`--check` 永远通过。

### 建议补：扩展门禁覆盖面

| 缺口 | 建议 |
|---|---|
| 42 条仅非 GET 路径 | 用固定夹具 + 幂等体（如 `POST /api/cards` 建卡后立即 `DELETE`）覆盖关键变更端点；至少覆盖 `cards` / `memory` / `task` 三类 |
| 5 条动态段 GET | 夹具已建 5 条 memory（含 1 任务卡），可直接用其 id 构造 `/api/cards/:id`、`/api/cards/:id/comments` 等 |
| 鉴权维度 | 现仅验「无令牌 401」；建议对每个受保护路由再验「有令牌 200」 |
